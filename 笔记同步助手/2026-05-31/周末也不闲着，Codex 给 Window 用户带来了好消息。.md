发布时间：2026-05-31

周末也不闲着，Codex 给 Window 用户带来了好消息。  
  
昨天发现 OpenAI 的 Codex 给 Windows 开发者带来了好消息，Computer Use 支持 Windows 了，现在可以在本地 Windows 环境中测试、调试和审查代码，同时支持通过 ChatGPT 移动端远程操控 Windows 机器，这意味着 Codex 快速做到了主流桌面平台全覆盖。  
  
同时 Codex 还更新了一个新特性，进入 设置 - 个人资料页，你可以看到自己日常的 Token 活动，类似 Github commit 的 像素 identicons，还有你消耗的 Token 总数，我现在在 Codex 里消耗了十几亿 Token 了。  
  
著名的 CC Switch 项目已经开始支持切换 Codex 的配置，你可以使用官方的 GPT 模型额度，也可以订阅国产大模型的计划，驱动 Codex App，并且可以随时通过 CC Switch 进行切换。  
  
我认为 Codex App 是一款对初学者非常友好的 Agent，事实上墨问 Vibe 计划群里的小白用户苏卡，加入几天之后就写出了自己的一个软件：  
  
[学习音乐的网页版「和弦听辨」，支持学习模式、练习模式、成绩统计](javascript:void\(0\);)  
  
Anthropic 也没闲着，推出了 Opus 4.8，还在 Claude Code 里推出 Dynamic Workflows 和 Agent View，这两个特新都相对专业，我后续再讲。  
  
Cursor 发布 Composer 2.5 与云端 Agent 环境，Windsurf 在被 Cognition 收购后加速整合 Devin，Google 则把 Gemini CLI 迁移到 Antigravity CLI。  
  
xAI 也没有站在场外，它一边接入 OpenClaw、Hermes 这类本地优先 Agent，一边推出 Grok Build 终端编码 Agent。  
  
在 Coding Agent 赛道，现在竞争的是谁能让 Agent 真正在工程系统里长期工作。读懂代码库，运行测试，提供友好的用户会话场景，还需要能经得起企业的权限、审计、数据验证。  
  
为啥这么卷呢，我看是市场在持续撑高这个领域的天花板。编程 Agent 的战场，已经从“写代码”转移到了“交付工作”。  
  
关于写代码的重要性，Vibe 群里的同学还分享了他们的团队实践：我们更关注需求侧 Agent 辅助梳理和基于 User Story 的场景测试验收这两个单点。之所以把中间代码产生过程的全自动放掉了，因为我们判断当前不是瓶颈。  
  
我的认知是，就目前 AI 的能力，对于工程师团队需要看看代码和中间过程的。对于普通用户（非编程背景）肯定会丢掉这一步，比如苏卡那个音乐程序，她只看结果就可以，看也看不懂。  
  
在未来，我想，当 Agent 能力越来越强之后，人类开发者的新工作应该是调度、观察和决策。
