# 结营成长报告 · 总结方法论

本文件指导 Agent 如何从学员的真实作业数据，写出「年度总结 / Spotify Wrapped」风格的成长报告。
核心理念：**这是给学员本人的纪念与鼓励，不是批改评语**。用数据高光 + 关键词 + 金句 + 宏观叙事，替代「建议①②③」式批改腔。

---

## 0. 总原则（必须守住）

- **口吻**：年度总结 / 结营纪念。像一份「这十多天你走过的路」的数据故事。
- **基调**：务实、真诚、鼓励。突出「每一个新开始、小成就、突破、咬牙坚持都值得被看见」。
- **禁三条**：
  1. 禁肉麻客套：不要「—— 你的志愿者，为你骄傲……」这种抒情署名。
  2. 禁批改腔：不要出现「建议、改进、不足、请加强」等评语式措辞。
  3. 禁「缺」字：毕业标准就是打卡达标，达标即毕业；个别日历日没打卡但总数已够，**绝不写「缺某天 / 缺勤」**，那是误导。
- **真实优先**：所有金句、小成果、侧写必须来自学员作业原文，不做无依据拔高。

---

## 1. 数据来源

每位学员一份 `data/graduated_{星球编号}.json`，结构：

```
{
  "student": { "id":"星球编号", "name":"微信昵称", "days":达标天数 },
  "homeworks": [
    {
      "星球编号":"66407", "微信昵称":"Yoyo Chen",
      "星级": 3,                       // 1-3，由 ant-rate-star-full 计数
      "好事状态":"已通过" / "—",
      "打卡时间":"2026-07-10 23:34:49", // 真实时间，渲染时必须按此升序
      "今日行动":"…", "今日收获":"…", "好事分享":"…", "下一步行动":"…"
    }, ...
  ]
}
```

写侧写前，**通读每位学员的全部作业四字段**，提取事实，再落笔。

---

## 2. 五维能力画像（雷达图，每项 1–5 分）

按作业行为证据打分，避免拍脑袋。定义与判据：

| 维度 | 含义 | 高分信号（4–5） | 低分信号（1–2） |
|------|------|----------------|----------------|
| **工具攻坚** | 踩坑、排雷、把工具跑通的能力 | 多次独立解决报错、换方案死磕到底 | 常卡住、依赖他人、未真正跑通 |
| **方法论** | 抽象、框架化、沉淀可复用方法 | 提炼原则/公式/清单、建标准 | 记步骤、零散、无体系 |
| **商业化** | 用户/客户/转化/生意视角 | 谈客户画像、私域、转化闭环 | 只谈工具、无受众意识 |
| **坚持韧性** | 在困难/加班/落差下持续行动 | 全勤、深夜仍学、想放弃又捡起 | 中断多、易放弃 |
| **输出质量** | 产出成果的可信度与完成度 | 跑通流水线、成稿、可交付物 | 半成品、空话 |

给分建议：以「同期学员中位数」为 3.0，明显强于多数给 4.0+，明显弱给 2.0。五维总和不宜全 5（失真），保留真实差异。

---

## 3. 小成果墙（8–12 项芯片）

从作业四字段里**筛具体动作与产出**，不要写感想。句式：`动词 + 具体对象/结果`。
- ✅ 「跑通 Codex 中文显示」「飞书机器人死了又救终上线」「整理环境差异清单」
- ❌ 「很努力」「进步很大」

来源优先级：今日行动 > 今日收获 > 下一步行动中已完成的 > 好事分享。覆盖工具、方法论、输出三类，避免全是同一类。

---

## 4. 高光时刻 & 咬牙瞬间

- **高光（hl / hlWho）**：选学员说过的、最有代表性的**原话金句**（带洞察/转折感的那句），hlWho 注明出处（第几天·日期·情境）。优先选「认知跃迁」类，而非「我完成了 X」。
- **咬牙（grit）**：选一个学员**坚持/想放弃又扛住**的瞬间，一句带过，体现韧性。用学员自己的表述口吻。

两者都必须是真实存在的，不编造。

---

## 5. 学员侧写三问（profile 数组，3 张卡）

基于作业行为**侧写**，不是评价。每段 2–3 句，务实、有依据：

1. **你是一个什么样的人**：从坚持模式、面对困难的反应归纳（如「最坏环境里也能把事做成的人」）。
2. **你擅长什么**：从高频行为提炼稀缺能力（如「踩坑、记坑、填坑，把混乱拧成全景图」）。
3. **你的潜力**：从现有能力推导下一步可能（如「环境一旦顺了，经验会让你跑得比谁都稳」），并落到「下一步可做的微小行动」上——但**用陈述式暗示**，不用「建议你去做」。

写法：先给一个画像判断，再用「因为你在作业里……（具体事实）」佐证，最后一句向前看。

---

## 6. 封面与数据卡（tagline / oneliner / stats / keys）

- **tagline**：宏观人设短句（如「在工具泥潭里一次次爬起来的『死磕型』」），点出最鲜明的特质。
- **oneliner**：一句话总结这十多天（如「用 12 天，把一个总想放弃的自己，熬成了一条能跑的内容生产线」），含天数+转变。
- **stats（4 个数据卡）**：文案可自定义，建议含「打卡天数 / 平均星级 / 满星次数 / 最强维度（或全勤）」。值由脚本自动算的用真实值，文案自定。
- **keys（3–6 个关键词）**：年度关键词标签，从成果与特质里提炼（如 死磕、流水线思维、API、排雷）。

---

## 7. 结营寄语（wish）

一段，务实向前看。可以点一个「把经验产品化 / 教别人 / 跑通第一单」这类具体而微小的下一步，但**用鼓励式陈述**，不写「建议」「希望你能」。语气示例落点：肯定其最值钱的特质，指向可自然发生的下一步。

---

## 8. 长度与密度建议

| 字段 | 建议长度 |
|------|----------|
| tagline | ≤ 20 字 |
| oneliner | ≤ 40 字 |
| hl（金句） | 学员原话，≤ 40 字 |
| grit | ≤ 35 字 |
| 每个 chip | ≤ 18 字 |
| 侧写每段 | 40–70 字 |
| wish | 50–90 字 |

整份报告目标：信息密集、有设计感、两页 A4 刚好铺满，不空洞也不堆砌。

---

## 9. 铁律：时间序列必须升序

渲染日历与星级曲线时，脚本已按 `graduated_*.json` 的 `打卡时间` 升序排列（D1=最早一天）。**撰写侧写时也绝不要颠倒时间顺序**——提到「第几天」「压轴日」须与真实日期一致。
