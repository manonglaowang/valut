# 项目架构与工程方法论

> 源：`docs/architecture_decision.md` / `docs/development_guide.md` / `docs/app_automation_integration.md` / `docs/firmware_pytest_quickstart.md` / `README.md`。这些是已经写成文档的工程决策，这里只提炼"为什么这么做"和"复盘时容易忘的关键点"，完整命令细节以仓库文档为准。

## 分层架构

```
script / tests / fixtures / hooks     ← 用例、框架自身测试、fixture 组装、pytest hooks
        ↓
   actions/scene                      ← 跨设备/跨原子能力的场景编排
        ↓
   actions/single                     ← 单个可复用原子动作
        ↓
logic（protocol/transport/session/client/adapter）/ reporting / core
```

强制依赖方向：底层不得反向导入上层。`actions/scene` 依赖 `actions/single` 和 `logic`；`actions/single` 只能依赖 `logic/core`；`logic` 不表达测试步骤、不依赖 pytest。业务脚本只表达输入、动作和断言；跨 suite 复用的流程进 `actions/scene`，只执行一个明确操作的能力进 `actions/single`。

用例分类用目录（`FN` 单功能 / `IN` 交互 / `LT` 压力 / `PR` 长稳），可重叠属性用 pytest marker（`smoke/regression/hardware/app/fw/destructive`），不为每种组合建目录或造 marker。

## 为什么单仓不拆双仓（对照旧项目 Poseidon_SA525M + TestScript_SA525M）

旧项目"看起来分体"的优点主要来自**命名职责清晰**，不来自两个 Git 仓库；把旧项目的隐式依赖复制过来只会让目录更整齐、运行更脆弱。旧项目的具体反面教材：

1. 用 `import *` 引入外部仓库的 hooks/fixtures，运行结果依赖工作目录或外部 PYTHONPATH，框架版本不可追踪。
2. import 时集中创建大量全局单例（设备连接/缓存/错误状态跨用例共享），破坏 fixture 隔离、并发和单测。
3. 进程级可变全局字典 + import 阶段探测磁盘并可能退出进程，这类副作用不该进可安装框架包。
4. 用 `eval` 动态生成 marker、把原始断言统一改抛通用异常，丢失 pytest 调用栈和失败类型。
5. 配置、路径、凭据混在可执行 Python 配置里，且 import 阶段执行 DNS——本项目改用 YAML 默认值 + CLI 覆盖 + 环境变量秘密 + LabProfile 能力门禁。

**只有同时满足以下条件才重新评估拆仓**：至少两个独立用例仓稳定消费同一框架；框架和用例有独立维护者/发布节奏；框架能构建 wheel 并通过 pytest11 插件公开公共 fixture；消费方精确 pin 版本；两边 CI 有 consumer contract test；配置/报告/资源路径已完全由运行时注入。在这些条件出现前，单仓能用一次变更同时验证 framework 与 consumer，是风险最低的方案。

## APP 自动化的演进：Midscene AI 识图 → WDA 元素树直连

iOS 录音导出已改为直接读取 WebDriverAgent `/source?format=json` 元素树，按 accessibility name/label/identifier 精确匹配点击，不再调用 AI 视觉模型：

```
pytest case → actions/scene → actions/single/app → logic/app/WdaElementSession → http://127.0.0.2:8100 → iPhone WebDriverAgent
```

`midscene_bridge/` 仍保留供 Android/OTA 用例兼容使用（`logic/app/MidsceneBridgeSession → http://127.0.0.1:4701`）。切换收益：**单条基础录音用例从 45-107 秒降到 35 秒**，且不再受 AI 识图不稳定性影响。

关键运维事实：预装 WDA 不能当普通 App 直接启动，它需要 `testmanagerd` XCTest 会话，否则以 SIGABRT 退出，必须走 `tools/start_preinstalled_wda_windows.py`。

## 选择器预检与自愈（App 版本漂移防护）

iOS App 改版导致 WDA 选择器整体失效时，夜间挂测不再级联失败：

- `ios_wda_session` 建连后比对 App 安装版本与 `selector_registry.py` 的 `CALIBRATED_APP_VERSION`，不一致自动先跑一轮逐页验证。
- 自愈规则：失效选择器做启发式匹配（identifier 命中 > 文本相似 > 类型兼容 > 位置邻近）；高置信候选热更新到 `reports/selector_overrides.json` 继续挂测；中置信只记录、相关用例带 `SELECTOR_DRIFT` 原因 skip；**危险动作键（OTA"更新"、解绑）永不自动生效**；导航关键选择器未自愈则整轮以 `SELECTOR_DRIFT` 单一原因中止。
- 次日晨检看 `reports/preflight/selector_drift_report.md`，确认后把新选择器合回代码常量、提升 `CALIBRATED_APP_VERSION`、删除覆盖文件。

这个机制的设计意图：**把"选择器漂移"和"真实业务 bug"分开报告**，避免版本升级当天整轮回归因为一堆选择器失效而被当成大量真实缺陷。

## 硬件动作约定（工程决策层面）

耳机压感自动化明确**不使用继电器**，固定走 `SingleUsbShell.single_bud_key()` 固件测试指令（详见 [[01-硬件实测踩坑知识]] 的归因过程）。这条约定写进了文档而不是只留在代码里，是因为"继电器能不能模拟压感"这个问题历史上被反复问起、反复验证过，属于应该被文档钉死、防止团队重复踩坑的结论。

## 运行方式速查（细节以仓库文档为准）

- 纯软件验证（不连真机）：`pytest tests/unit -q`，使用 fake serial/BLE/ADB。
- 真机固件冒烟：需要硬件 profile（`config/env.hardware.local.yaml`）声明 `serial/relay/midscene` 能力，加 `--serial-port` `--phone-uuid` `--run-destructive`。
- `destructive` 用例默认跳过（改变设备状态或数据的动作），必须显式传参执行——这是防止误跑破坏性操作的安全阀。
- FOTA 用例：命令下发成功不代表升级验证成功，当前结果字段固定 `upgrade_verified=False` / `commands_dispatched`，升级完成事件和版本校验仍是已知缺口，不能把"命令已发送"误报为"升级成功"。
- BLE 安全材料（RSA 私钥、鉴权签名等）只通过环境变量注入，不写入 YAML 或仓库。

## 已知的下一步/待补齐项（工程债务，复盘参考）

1. 需要固件头文件或抓包确认 seqNum 规范、ECC unbind payload、FILE_MANAGER ACK CRC 等契约，目前部分靠约定推断，不能用 encoder/decoder 自洽测试代替真实设备验证。
2. BLE ChaCha20-Poly1305 的方向密钥/nonce 规则待与固件共同修订，当前保持旧 wire 行为仅用于受控测试环境。
3. OTA 完成事件、重连后版本校验仍需补齐。
4. 解绑后 iOS 蓝牙"忽略此设备"清理尚未自动化（见 [[01-硬件实测踩坑知识]]）。
